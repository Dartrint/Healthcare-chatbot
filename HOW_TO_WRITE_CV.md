## Common Interview Questions - Answers

**Q: Why did you measure quality metrics?**
```
A: Because "it works" isn't enough for production systems. I wanted to quantify:
1. Relevance - Does the response match the user's query?
2. Coherence - Is the response well-structured?
3. Coverage - Does it address all aspects of the query?

This ensures consistent quality across different query types and identifies 
areas for improvement.
```

**Q: What was the hardest part?**
```
A: Getting the semantic embeddings right. Initially, relevance scores were 
low (0.65) because the model wasn't capturing medical domain nuances well. 
I switched to SentenceTransformers which improved relevance to 0.78.
```

**Q: How would you scale this?**
```
A: Several approaches:
1. Horizontal scaling - Add more API servers behind a load balancer
2. Vector caching - Cache frequently-accessed embeddings in Redis
3. Model optimization - Use quantization to reduce model size
4. Async processing - Move expensive operations to background jobs
Currently it supports 5+ users; for 100+ users, I'd implement these strategies.
```

**Q: Any metrics that surprised you?**
```
A: The coherence score (0.96) was higher than expected. Turns out LLMs are 
naturally good at structured responses. But relevance (0.78) was lower than 
expected because medical domain embeddings require careful tuning. This taught 
me the importance of domain-specific fine-tuning.
```
